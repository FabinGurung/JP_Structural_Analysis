1.2 Structural Modelling

What the original report says: It describes 3D ETABS frame modelling with centre-line dimensions, preliminary member sizes, concrete M20, rectangular-beam idealization, horizontal seismic effects along principal axes and a SAFE foundation model. It also claims linear static and response-spectrum methods. These statements document intent, but not a recoverable original element and load definition.

Our reproducible method: Python builds a provisional 3D finite-element frame and calls OpenSeesPy elasticBeamColumn. The current example solves gravity and four signed horizontal force cases (±X/±Y), preserving displacements, reactions and full signed local end forces. Every input is required to carry source or assumption provenance.

1.3 Structural System of the Building

Source intent: The report selects an RC Special Moment Resisting Frame. Beams and columns form a connected path for gravity and horizontal earthquake loads to reach the ground. It names adequate strength, lateral stiffness and serviceability as desired performance objectives.

Roof and floors gravity + horizontal loads↓Beams and slabs distribute load; slab diaphragm is unverified↓Columns + beam joints carry axial force, shear and moments↓Foundations → ground soil bearing, shear and settlement checks

What this does not prove: An SMRF label in the source is not a check of confinement, strong-column/weak-beam relationships, joint shear, reinforcement anchorage, column continuity or foundation safety. Those are tasks for Chapters 2, 5 and 6.

2.0.1 · How do we actually find the supports and where forces act?

The OpenSees program does not discover ground supports or loads by itself. We identify them from real structural and foundation drawings, member/joint continuity, soil parameters, actual occupied space, member selfweight and code-governed earthquake/wind actions.

AssignmentEvidence needed before modellingOur current state
Base / foundation restraintsFoundation plans, support details, geotechnical inputs and intended fixityNOT VERIFIED · trial fixed supports only
Slab, selfweight and wall loadsPlan geometry, dimensions, materials, openings and actual load locationsNOT VERIFIED · source magnitudes insufficient for assignments
Live load / occupationReal room use plus applicable occupancy-load standardNOT VERIFIED · mixed-use conflict
Seismic and wind actionsVerified Pokhara site, mass, editions, exposure and code proceduresNOT VERIFIED · site-specific governing inputs incomplete

Each value must have its own source and target ID before analysis. A finished PDF can report 6,831.9109 kN seismic weight without proving which slab and wall objects supplied that weight.

See the real OpenSees, manual mathematics, Three.js and SVG linked example at More → FEM solving lesson. The teaching support/force are declared assumptions, not G+1.5 evidence.

4.1 3D View of the Building · FE discretization

OpenSeesPy 3D elasticBeamColumn, six degrees of freedom per node, fixed-base supports, assumed beam topology and source-derived column coordinates. Default trial includes 165 members, 92 nodes and two unverified beam connections repeated at three levels.

Selfweight, distributed wall loads, actual slab shells and complete diaphragm assignments are not represented in the default five-case report.

4.2 Load Application · equilibrium

The solver executes GRAVITY, EQ_PLUS_X, EQ_MINUS_X, EQ_PLUS_Y and EQ_MINUS_Y. Each run checks global force and moment equilibrium.

ΣF(applied) + ΣF(reactions) ≈ 0ΣM(applied) + ΣM(reactions) ≈ 0

Passing equilibrium proves numerical consistency, not that source drawings, actual mass or member capacity are correct.
