01
THE BIG PICTURE

One robot. Several different jobs.

Think of a school science project. First you draw something; then you try an experiment; then you record what happened; finally you write a report.

And who does which job?

3D Studio lets you see the working building. Run Analysis is a small practice playground. Project Lab is our experiment notebook. Calculation Coverage is the list of lessons our robot has learned. GitHub Actions is the automatic computer worker. GitHub Pages displays the website. Report is the readable result at the end.

OpenSees: the real calculating engine inside our system

OpenSees is not another web page, not Python itself, and not a ready-made reinforcement design report. It is the finite-element solver: we tell it the frame, supports, materials and loads; it solves the equations and returns displacements, reactions and member actions. OpenSeesPy is the Python interface that lets our scripts operate it.

VIEW 4 · Follow the manual mathematical solution

  1. Choose a model: one elastic beam; base translations and rotation fixed; top free. Not a statement about real foundation behaviour.
  2. Section stiffness: I = b h³ / 12, then EI = E × I. Checking geometry…
  3. Build the 2×2 free-end stiffness matrix: K = EI/L³ × [[12, −6L], [−6L, 4L²]]. Solve K[u,θ]ᵀ = [F,0]ᵀ.
  4. Manual deflection: u = F L³/(3EI), θ = F L²/(2EI). Checking deflection…
  5. Independent equilibrium: Rₓ = −F; M(base) = FL. Checking moments…
  6. Check numerical agreement: Loading verified case…

This one-element Euler–Bernoulli benchmark is solvable by hand. Large buildings use interconnected stiffness matrices and more complex material behaviour. Numerical agreement alone does not establish physical modelling validity.

ONE IMPORTANT DIFFERENCE

Making a beautiful drawing of a bridge does not prove the bridge is strong. In the same way, seeing our building in 3D does not mean we have checked every beam, slab and footing.

Check your understanding: Which tool is the final notebook, and which tool is the workshop diary?

Report is the final notebook. Project Lab is the workshop diary. Both are valuable, but they answer different questions.

What we actually built

Our larger working model uses source-derived column locations and a proposed connecting frame. You can rotate it, choose a beam or column, change trial stiffness and loads, and inspect signed numerical results. An authorized GitHub job can solve the selected configuration using OpenSees.

Some beam connections were inferred, and two additional connectors are specifically hypothetical. The preview does not yet include a verified full slab, diaphragm or wall-load map. It is a model under investigation, not a finished digital copy of the building.

Can do

ANALOGY TO REMEMBER

The 3D Studio is like a model airplane. You can hold it and understand where the wings are, but before flying a real aircraft you must verify every part—not just how the model looks.

Try explaining: If I rotate the model and it looks perfect, is the structural design approved?

No. Turning a model is a display action. The design still needs correct source inputs, loading, analysis, reinforcement and independent engineering checks.

03
THE PRACTICE CALCULATOR

Run Analysis: what happens if we push the building?

Imagine a toy tower. What happens if you make it heavier, taller or less stiff, then push from one side? We use maths and a computer to investigate questions like that.

Practice runner: 2D

One small single-bay, three-level teaching frame viewed from one direction. You can edit its heights, widths, weights and earthquake parameters.

3D Studio: larger frame

A provisional project-inspired frame with members across two horizontal directions. It is a different model, not an automatically enlarged copy of the 2D toy.

There are two stages: a quick answer and a serious calculation

STAGE A · INSTANT PREVIEW

A small calculation in the web browser

When you change a number, JavaScript works out an equivalent-static earthquake force. It does not solve the complete frame. Think of it as a pocket calculator.

STAGE B · SUBMITTED SOLVE

OpenSees on a GitHub computer

Submitting an authorized synthetic case starts a GitHub Actions job that runs the actual finite-element mathematics, producing support reactions and member-end forces in a downloadable result.

Why not run everything inside the website?

The website can show a fast formula, but OpenSees is a separate engineering program. For the real solve, the website helps prepare a safe numerical request; an authenticated GitHub issue and an authorized Actions workflow run the solver. A public visitor cannot secretly trigger expensive or private calculations merely by scrolling.

Prediction: If W changes from 300 kN to 600 kN, and Cd stays 0.10, what happens to V?

It doubles: 0.10 × 600 = 60 kN. That is a fact about this equation. It does not say the real building will behave in exactly the same way when other assumptions change.

THE SCIENCE NOTEBOOK

Project Lab: what have we tried, and what did we discover?

A scientist doesn't erase the experiment that went wrong. They write down what they tried, what they expected and what they actually saw. Project Lab is our memory of the engineering investigation.

Our real experiments, explained

Gates 08–10Where does the weight come from?

We compared source reports with assumed walls, footprints and floor weights. Making the totals match by inventing a wall would be cheating, so unresolved mass stays unresolved.

Gates 11–16Does the model change when the floor changes?

We tested assumed diaphragm stiffness, slab shells, meshes, openings and torsion. These are sensitivity studies, not evidence that the original floor shape has been recovered.

Gates 17–20Can we trace the source and the foundation failure?

We documented the original report's conflicting numbers, missing ETABS model, seismic weight and footing F3. Fifteen source-to-model evidence obligations were defined and remain open.

WHY THIS MATTERS

If two computer models disagree, Project Lab helps us find which assumption changed. It does not let us simply choose whichever answer looks safer.

What should our robot do if a load value is missing?

Label it unknown, or use a clearly stated, cited trial assumption for exploration. Never pretend the assumption came from the original ETABS file.

What is the difference between *calculated* and *safe*?

If a calculator tells us a beam has a bending moment of 25 kN·m, it has answered “What force is happening?” It has not yet answered “Can the actual beam and its steel reinforcement resist that force?” That second question needs the correct member, material, reinforcement, load combinations and design rules.

Structural analysis

Find the forces and movements when loads act on a model.

Structural design

Check or choose real beams, columns, slabs and reinforcement that can resist the required forces under applicable rules.

Can we mark every column “SAFE” just because OpenSees finished without an error?

No. A solver finishing is like a calculator returning a number. We still need the right physical model, load combinations and independent capacity/detailing checks.

THE AUTOMATIC WORKER AND THE LIBRARY

GitHub Actions, Pages, examples, demos and old versions

Here is the easiest memory trick: GitHub stores the instructions, Actions does the work, and Pages displays the result.

There are really three kinds of automatic jobs

TEST“Did we break the software?”

Regression tests compare code against expected numerical results and safety flags.

ANALYZE“What did this chosen model calculate?”

Authorized solver jobs run OpenSees and publish machine-readable results, member forces and logs.

PUBLISH“What can the reader see now?”

The Pages build checks a pinned tested source version, regenerates allowed report outputs and deploys the website.

Why are there old examples and demo files?

Sanitized two-span beamA small practice question with known context

Imagine two bridge spans sharing a middle support. We use that clean example to compare forces, moments and reactions, and to detect calculation mistakes. It has a recorded reaction-reconciliation HOLD; it is not the G+1.5 building.

Demo report · SARA sample of the final writing format

It shows how a Structural Analysis Report can present methods, calculations and results. A nice report layout does not certify the example or the real project.

JSON and CSV filesThe robot's written arithmetic

JSON stores labelled model inputs and numerical outputs. CSV gives rows of member actions in a spreadsheet-friendly format. Checksums help confirm that a file has not changed unexpectedly.

Frozen Seq9 release and Git historySaved photos of older versions

A tag is like putting an old, working robot in a glass cabinet. We can inspect or restore its source without deleting what we built afterward. Commits explain what changed and when.

Developer rules and code inventoriesThe robot's instruction manual

These contain the typed model structures, standards references, numerical tests and rules for connecting evidence to results. An old ETABS E2K file can be imported when available, but we do not pretend one exists.

A COMMON CONFUSION

If GitHub says “360 tests passed,” it means the software passed those tests. It does not mean the building passed 360 different safety inspections. A green computer check and a signed engineering design are not the same thing.

Explain this to someone else: Are GitHub Actions and GitHub Pages the same thing?

No. Actions is the worker that runs programs and produces files. Pages is the bookshelf where visitors read the finished website. The repository keeps the recipes and history.

SMALL DICTIONARY

Ten words that were making this confusing.

You don't have to memorise them; use them when you find them in our report.

Model

A mathematical copy of a structure. It may use assumptions.

Solver

The program that solves the structural maths, like OpenSees.

Finite element

A small piece of a bigger structure that the computer uses to calculate forces and movements.

Load

A force or weight acting on the building.

Reaction

The push back from a support when a structure is loaded.

Drift

How much one floor moves sideways compared with the floor below it.

Source

The original drawing, report, rule or measurement that supports an input.

Assumption

A clearly named guess used for a trial because the real value is unavailable.

Regression test

A repeatable check that an old feature still behaves as expected after software changes.

Engineering approval

An actual professional design acceptance based on verified evidence—not just a green computer message.

REMEMBER THE CONNECTIONS

One-minute teach-back challenge.

Before opening an answer, try explaining it out loud as if you were teaching a younger child.

1. Which page is our experiment diary, and which page shows the report?

Project Lab records the trials and uncertainties. Report arranges the current evidence in the original source chapter order.

2. Why do the practice 2D frame and working 3D building give different answers?

They have different shapes, loading and assumptions. The small one teaches methods; the provisional 3D one explores the actual project's source-derived frame.

3. Can a number be mathematically correct and still be unsuitable for construction?

Yes. For example, a correct formula using an invented slab thickness may produce a correct answer for the invented slab, not the real slab.

4. What will make the robot closer to a real structural design engine?

Verified drawings and load paths; authenticated materials, mass and soil; complete governing load combinations; modal/drift and second-order checks; RC member/slab/foundation design; independent reconciliation and review. In particular, the original F3 shear failure needs a separately verified correction.

The one sentence worth remembering:

We built a real numerical calculator, a trial 3D building, an experiment notebook and an automatic report factory—but the inputs and full structural design still need to be proven.
